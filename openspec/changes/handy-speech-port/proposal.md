# Proposal: Handy-класс диктовки в Tempo

## Почему

Модуль диктовки в Tempo сегодня — каркас: четыре модели без проверки целостности, голый
список в настройках и **зашитый Ctrl+Shift+D, который умеет только toggle**. Клавиша-хоткей
из настроек не подключена ни к чему, отпускание клавиши игнорируется, поэтому «зажать и
наговорить» физически невозможно. Пользователь просит уровень Handy (31995 звёзд, MIT):
менеджер моделей с выбором и разворачиванием, честный push-to-talk и сопутствующие
настройки — всё локально, без облака.

## Что меняется

Волны (детали в `tasks.md`, контракты в `interfaces.md`):

1. **W1 Backend core** — каталог моделей (`catalog.json`, ≥20 позиций Whisper с квантами,
   sha256, зеркалами, оценками скорости/точности, `revision`-пином), новый загрузчик
   (возобновление, stall-timeout, верификация хэша, скорость и ETA), чистый автомат
   активации `CoordinatorState` (три режима, DEBOUNCE 30 мс, RELEASE_GRACE 50 мс, порог
   300 мс, очередь нажатий на время распознавания), динамическая регистрация хоткеев,
   аудиовход (устройства, канал, VAD Energy/Earshot с prefill/onset/hangover), звуковой
   отклик, история в SQLite, пост-обработка через существующий `ai.rs`.
2. **W2 Integration** — сборка всего в `stt/mod.rs` и `lib.rs`: командный фасад, `SttState`,
   старт приложения (регистрация хоткея до открытия окна), фикс незарегистрированной
   `stt_cancel_transcription`, компиляция и `cargo test`.
3. **W3 Frontend** — сервисный слой (типизированные команды, события вместо polling,
   полный набор префов) и UI в существующей вкладке «Speech to Text»: библиотека моделей,
   захват хоткея, режимы, аудио, VAD, язык, словарь, вставка, звуки, история, пост-обработка,
   онбординг первого запуска, диагностика.
4. **W4 Acceptance** — слепая приёмка oracle по этому брифу, затем `bun run check:all` и
   ручной прогон в собранном приложении.

## Не делаем

- Второй движок (Parakeet/Nemotron/SenseVoice через ONNX): выбор пользователя — только Whisper.
- Silero VAD: тянет ONNX Runtime в установщик; VAD-бэкенды Energy + Earshot.
- Второй низкоуровневый бэкенд клавиатуры (`handy-keys`) и macOS-специфика (clamshell,
  Apple Intelligence): платформа проекта — Windows.
- Облачную транскрипцию не трогаем — она уже работает (`cloud.rs`).

## Риски

| Риск | Ответ |
|---|---|
| Пять параллельных исполнителей в одном Rust-крейте не соберутся по отдельности | Файлы разведены по владельцам, интерфейсы заморожены в `interfaces.md`; сборку делает одна интеграционная волна |
| Ошибки компиляции после параллельной волны | Интеграционный агент владеет `lib.rs`/`mod.rs`/`dictation.rs` и обязан довести `cargo test` до зелёного |
| Хоткей может конфликтовать с системным | `stt_validate_hotkey` возвращает причину отказа, UI её показывает |
| Глобальный хоткей и запись живут вне окна | Регистрация на старте приложения из префов SQLite, а не из UI |
| Скачивание больших моделей (до ~3 ГБ) | Возобновление, отмена, проверка свободного места, sha256 перед установкой |
