# Interfaces: диктовка должна быть видна и слышна (заморожено 2026-09-24)

Запрос: «Ничего не работает» → после починки цепочки остаётся вопрос: **как пользователь узнаёт, что
происходит**, когда диктует в другом приложении, а не в Tempo. Разведка нашла четыре дыры видимости.

## Дыры, подтверждённые чтением кода

| # | Что | Где |
|---|---|---|
| 1 | Ошибка диктовки показывается **только внутри раздела STT** | `SpeechPanel.tsx:281`, `actionError` живёт в панели |
| 2 | Событие `stt://hotkey-error` не слушает **никто** | бэкенд шлёт (`mod.rs`), в `sttEvents.ts` его нет |
| 3 | Событие `stt://vad-fallback` не слушает **никто** | там же |
| 4 | Пока идёт распознавание, на экране ничего нет | `DictationIndicator.tsx` гаснет на отпускании, хотя движок ещё считает |

## Замороженное решение

1. **Всплывающая плашка ошибок** поверх любого экрана: слушает `stt://speech-error`,
   `stt://hotkey-error`, `stt://vad-fallback`, `stt://model-failed`; показывает причину человеческим
   текстом, живёт 8 секунд, закрывается кликом. Одна на все экраны, а не внутри раздела.
2. **Состояние обработки в индикаторе**: пока движок считает, индикатор остаётся видимым и показывает
   «Распознаём…», а не исчезает мгновенно.
3. **События в типах**: `SttEvent` расширяется `hotkey-error` и `vad-fallback`, чтобы их нельзя было
   молча не обработать.

```ts
// src/services/sttEvents.ts — замороженные дополнения
| { type: 'hotkey-error'; hotkey: string; message: string }
| { type: 'vad-fallback'; backend: string; reason: string }
```

## Доказательство

- Тесты: событие ошибки рисует плашку с текстом; плашка закрывается кликом; `hotkey-error` и
  `vad-fallback` доходят до подписчиков; индикатор показывает «распознаём» между отпусканием и
  результатом и скрывается после.
- Живой экран: плашка появляется при отказе клавиши и при ошибке распознавания.
