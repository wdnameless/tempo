# Proposal: связный MVP — будильники, ИИ-ассистент, единый вид

## Почему

Приложение отвечает текстом, но не меняет то, что вы видите: ИИ пишет в SQLite, React об
этом не узнаёт (`App.tsx:195`), чат не умеет создавать будильники (проп `onApplyAlarms`
выбрасывается в `AIChatDrawer.tsx:36`), а в модели будильника нет ни даты, ни интервала —
их физически некуда положить. Плюс два параллельных ИИ-конвейера (`ai.ts` в модалке
`Alarms.tsx` и `aiCompiler.ts` в чате), которые не знают друг о друге.

## Что делаем

Четыре среза, контракт между ними заморожен в `interfaces.md`.

1. **S1 — ядро расписания (Rust).** Модель будильника расширяется датой и интервалом с
   окном; `sync_alarms` остаётся единственным путём записи; Rust считает ближайшие
   срабатывания и отдаёт их фронту одной командой (`alarm_preview`), чтобы логика
   расписания не разъехалась в двух языках. Тесты: дата, интервал, окно, переход через
   полночь, старое поведение не сломано.
2. **S2 — экран будильников (UI).** Создание и правка в одном месте, все поля доступны
   сразу (включая заметку), список показывает «следующее срабатывание», вид — только на
   токенах и примитивах. Модалка ИИ-расписания внутри будильников удаляется: её роль
   забирает чат.
3. **S3 — ИИ ↔ состояние приложения.** Один конвейер: `create_alarms` добавляется в схему
   компилятора, ответ модели показывается карточкой превью, после подтверждения будильники
   пишутся и **сразу** появляются в интерфейсе (единый сигнал об изменении данных,
   на который подписан `App.tsx`). Заодно: `mins` из таймер-интента применяется,
   `unrecognizedCommand` задействован.
4. **S4 — единый вид.** Общие примитивы (карточка, заголовок экрана, пустое состояние)
   и проход по основным экранам: убрать сырые значения, привести карточки и отступы к
   токенам.

## Не делаем

- Полный арт-передел каждого экрана — вместо этого единые примитивы и токены (см. таблицу
  отклонений в `manifest.md`).
- Снуз/звук на каждый будильник, синхронизация будильников между устройствами.
- Новые внешние зависимости: и так уже есть React, Rust, `transcribe-cpp`, `rodio`.

## Риски

| Риск | Ответ |
|---|---|
| Три исполнителя в одном дереве | Файлы разведены по владельцам в `interfaces.md` §1; каждый работает в изолированном worktree |
| Миграция БД ломает старые будильники | Новые поля nullable, старые значения читаются как раньше; тест на «старый будильник всё ещё звенит» |
| Логика расписания разъедется между Rust и UI | Ближайшее срабатывание считает только Rust; UI показывает то, что вернул backend |
| ИИ создаёт мусор | Превью + подтверждение; без подтверждения в базу не пишется ничего (R04) |
