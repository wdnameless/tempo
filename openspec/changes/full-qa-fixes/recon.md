# Recon: полный QA-прогон приложения

Запрос: «ПОищи баги, протестируй весь функционал и пофикси дефекты. Я хочу готовое мвп».

## Метод

Шесть независимых проверок по областям (агенты-тестеры, только чтение + одноразовые пробы в
`.tmp/`) плюс мой собственный проход по интерфейсу в браузере (`bun run dev` + живой клик по
экранам с перехватом необработанных ошибок).

Правило для проверок: доказательство обязательно — падающий тест, вывод команды, состояние
базы или файла, скриншот. «Посмотрел код, выглядит верно» доказательством не считается.

## Три самых важных (объясняют жалобу «ничего не работает»)

1. **Ассистент всегда в офлайне.** `aiCompiler.ts:444` проверяет `settings.apiKey`, который
   намеренно всегда пустой (ключ лежит в системном хранилище) → удалённая модель не вызывается
   никогда, даже когда ключ сохранён. Онлайн-разбор расписаний не работал в принципе.
2. **Будильники из ИИ звонят не в те дни.** Компилятор нумерует дни с понедельника, планировщик
   и интерфейс — с воскресенья. «Пн, Ср, Пт» превращается в воскресенье, вторник, четверг.
3. **Кнопка «Стоп» не останавливает запись.** `stt_stop_dictation` посылает «отпускание», которое
   автомат в режиме Toggle игнорирует → диктовка продолжается бесконечно.

## Проверка приёмки

1. Каждый дефект закрыт правкой с регрессионным тестом, который падал до неё.
2. `cargo test` и `cargo clippy --all-targets -- -D warnings` зелёные; `bun run check:all` зелёный.
3. Сборка `tauri build --no-bundle` и запуск собранного приложения.
4. Повторная слепая приёмка (oracle) по реестру дефектов.
