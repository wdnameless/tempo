# Blind audit: шумодавы и модели (2026-09-24)

`VERDICT: ACCEPT-WITH-CAVEATS`

Два слепых прохода одним аудитором, без моей спецификации — только по запросу пользователя:
«Добавь всякие шумодавы, и STT должен быть список из локальных моделей которые есть в handy и
интерфейс еще можно доработать» (+ ответы: RNNoise + DSP + Silero VAD; весь набор Handy; список
моделей в мастере).

## Первый проход (выпущенное 0.23.3/0.23.4) — отклонено, семь дефектов

Все семь — у пользователя, не теория:

1. `denoise.rs:258-263` — гейт (включён по умолчанию) рубил речь: целые кадры по 30 мс
   обнулялись без атаки/затухания, тихие согласные и хвосты слов пропадали, границы щёлкали.
2. `recording/audio.rs:511-516` + `denoise.rs:149,217` — цепочка пересоздавала состояние
   на каждом колбэке CPAL: RNNoise терял непрерывность (то есть не работал), сбросы давали
   щелчки в записях.
3. `denoise.rs:298-316` — AGC подкачивал: включался до −80 дБ, давал до 30× за 60 мс, дыхание
   между словами и zipper-шум без рамп.
4. `mod.rs:432-436`, `vad.rs:275-296` — ложное «Silero не установлен»: путь искался по жёстким
   Windows-каталогам вместо менеджера моделей, портативная установка страдала.
5. `vad.rs:566-571` — тихая деградация: падение Silero молча подменялось энергетическим VAD.
6. `capture.rs:388-394` — метр проверки микрофона мерил сырой вход, до цепочки.
7. `recording/audio.rs:338`, `recording/mod.rs:176` — внутренние сессии записи игнорировали
   сохранённые настройки.

## Второй проход (после правок) — принято с оговоркой

Шесть из семи исправлены полностью; седьмой — метр — был закрыт на бэкенде, но фронтенд всё
ещё предпочитал браузерный анализатор (`AudioSettings.tsx:153-205`) и мерил звук до цепочки.
Исправлено в `059b6c9`.

Новых проблем не найдено: утечек нет, проба уровня сама останавливается после 1.5 с тишины.

## Что осталось непроверяемым

Живой акустический тест на микрофоне — автоматика этого не проверяет; проверено тестами блоков
и цепочки целиком.
