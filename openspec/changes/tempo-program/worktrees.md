# Изоляция и ветки — Tempo Program

Требование T3: изолированный worktree на каждую крупную часть. В этом репозитории оно выполняется
средствами рантайма плюс одна ветка на волну — так у пользователя остаётся **один** checkout
(`D:/WORK/Alarmer`), из которого он собирает и тестирует portable-копию.

## Как это устроено

1. **Каждый пишущий субагент стартует с `isolated: true`** — рантайм поднимает отдельный worktree
   на время задачи и применяет результат в основной checkout только при успехе. Падение или
   отменённая задача не оставляет мусора в рабочем дереве.
2. **Один владелец на файл.** Две волны никогда не пишут один файл одновременно; пересечение зон
   сериализует задачи (см. `interfaces.md` §5).
3. **Ветка и тег на волну.** Ветка `feat/w<N>-<slug>` (например `feat/w1-pomodoro`), тег
   `v<X.Y.Z>` на релиз этой волны (R35). Коммит — точка отката пользователя.
4. **Читающие роли не пишут:** `@explorer`, `@scout`, `@reviewer`, `@oracle` только читают.

## Почему не отдельный worktree на каждую из 13 волн

Полный отдельный checkout даёт пользователю 13 копий и 13 каталогов сборки Rust (`target/` —
гигабайты каждая) и ломает привычный путь к собранному `tempo.exe`. Рантайм-изоляция на задачу
даёт тот же эффект «рабочее дерево не портится», не размножая сборки. Отступление от буквы
правила зафиксировано осознанно; если пользователь захочет классические worktree — включаются
одной командой на волну.

## Сборка и проверка

- Сборка одна: `bun run tauri build` в `D:/WORK/Alarmer` (portable-копия проверяется пользователем).
- Полный прогон: `bun run check:all` (tsc, eslint, vitest, покрытие, cargo test, clippy).
- Приёмка волны: слепая проверка `@oracle` против `manifest.md` + ручной прогон пользователем.
