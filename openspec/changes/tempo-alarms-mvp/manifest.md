# Manifest: будильники + ИИ-ассистент (MVP)

Дословные цитаты пользователя (запрос 2026-09-22 + ответы виджета Wave 0):

- «Все очень плохо работает, функционал не связан с интерфейсом. Используй т3 воркфлоу, доделай мвп сам»
- «Самое первое это удобная система напоминалок\будильников и чтобы с ней взаимодействовал ИИ ассистент»
- «К примеру я закидываю ему текст со своим расписание или тренировками, он его анализируем и выставляет мне будильники по дате или по интервальному повторению»
- «Так же интерфейс должен выглядить стильно, мииниммалистично и функционально»
- «ai_mode: Разбор + превью + подтверждение»
- «scope: Всё приложение целиком»
- «pain: изменения не видны сразу» (первый по важности симптом)

| R## | Требование | Источник (цитата) | Проверка |
|---|---|---|---|
| R01 | Всё, что ИИ записал в базу, немедленно видно в интерфейсе — без перезахода на экран и без перезапуска | «функционал не связан с интерфейсом» + «изменения не видны сразу» | Единый сигнал об изменении данных; после подтверждения ИИ-превью список будильников и дашборд обновляются в том же рендере |
| R02 | Чат-ассистент умеет создавать будильники (сегодня не умеет: проп выбрасывается, интента нет) | «чтобы с ней взаимодействовал ИИ ассистент» | Интент `create_alarms` в схеме компилятора; `onApplyAlarms` доходит до применения |
| R03 | Текст расписания/тренировок превращается в список будильников, а не в задачи | «закидываю ему текст со своим расписание или тренировками … выставляет мне будильники» | `build_plan` больше не подменяет будильники задачами; прогон на реальном тексте тренировки |
| R04 | Перед созданием показывается превью: что именно будет создано, с датами и временем; создание — только после подтверждения | «Разбор + превью + подтверждение» | Карточка превью в чате: строки «когда / что», кнопки подтвердить и отменить; без подтверждения в базу ничего не пишется |
| R05 | Будильник можно поставить на конкретную дату | «выставляет мне будильники по дате» | Модель и UI: `date` (YYYY-MM-DD) + время; срабатывает один раз |
| R06 | Будильник можно поставить на интервальное повторение внутри дня | «или по интервальному повторению» | Модель и UI: «каждые N минут/часов» + окно «с HH:MM до HH:MM»; следующее срабатывание считается в Rust |
| R07 | Существующие режимы (ежедневно, дни недели) сохраняются и живут в том же интерфейсе | «Всё как в Handy»/текущее поведение | Старые будильники продолжают звонить; UI не различает старый и новый формат |
| R08 | Пользователь видит, когда будильник сработает в следующий раз | «удобная система напоминалок» | В списке и в превью — ближайшее срабатывание, посчитанное Rust (одна правда, не дубль логики в UI) |
| R09 | Создание и правка будильника — один экран, без модалок-лабиринтов | «удобная система» + «функционально» | Создание/правка в одном месте, все поля доступны при создании (включая заметку) |
| R10 | Экран будильников выглядит минималистично и в одних токенах с остальным приложением | «стильно, мииниммалистично и функционально» | Только токены `design.ts`/CSS-переменные, примитивы `ui/`, единые карточки и пустые состояния |
| R11 | Согласованность остальных экранов приведена к тем же правилам | «scope: Всё приложение целиком» | Задачи, заметки, календарь, статистика используют те же карточки/заголовки/пустые состояния; сырые tailwind-значения убраны |
| R12 | Мёртвые и дублирующие куски убраны, а не оставлены рядом | «доделай мвп сам» | Модалка ИИ-расписания внутри будильников удалена (дубль чата), `missed_alarms_today` либо используется, либо удалена; `unrecognizedCommand` задействован |
| R13 | Таймер, запущенный из чата, запускается с той длительностью, которую назвал пользователь | «функционал не связан с интерфейсом» | `onSetTimerMinutes(mins)` реально ставит таймер, а не просто переключает вкладку |
| R14 | Ничего не ломается у существующих будильников и тестов | «Все очень плохо работает» — значит чинить, а не переписывать вслепую | `cargo test` и `bun run check` зелёные; миграция не теряет старые будильники |

Отклонения, зафиксированные честно:

| Что | Почему | Потолок | Апгрейд |
|---|---|---|---|
| Полный арт-передел всех экранов | В приоритете связность и будильники; переписывать 20 экранов сразу — риск сломать работающее | единый набор примитивов и токенов на всех основных экранах | пошаговый редизайн экранов после приёмки MVP |
| Снуз и звук на каждый будильник отдельно | Не влияет на сценарий «расписание → будильники» | общий снуз 5/10/15 и общий звук, как сейчас | персональные настройки будильника |
| Синхронизация будильников между устройствами | Отдельная подсистема (journal/merge) | локально | переиспользовать существующий `sync/` |
