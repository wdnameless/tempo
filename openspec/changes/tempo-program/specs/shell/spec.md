# Спецификация: каркас и дизайн-система (Волна 0)

Формулировки нормативные: `MUST` — обязательное поведение, `SHOULD` — рекомендованное,
`MAY` — допустимое.

## ADDED Requirements

### Requirement: Единый визуальный язык
Интерфейс MUST использовать один тёмный стиль: почти чёрный фон, три уровня поверхностей,
тонкие разделители, Inter для интерфейса и моноширинный шрифт для чисел. Компоненты MUST брать
цвета только из токенов дизайн-системы; шесть прежних тем MUST быть удалены.

#### Scenario: Пользователь меняет акцент
- **WHEN** пользователь выбирает акцент из восьми в настройках
- **THEN** акцент применяется ко всем экранам через одну переменную, без перезапуска

#### Scenario: Старые темы в сохранённых настройках
- **WHEN** в старом файле лежит одна из шести прежних тем
- **THEN** приложение стартует в новом стиле, значение игнорируется, падения нет

### Requirement: Навигация из сайдбара
Экраны MUST переключаться из левого сайдбара: иконка и подпись, активный пункт выделен.
Сайдбар MUST сворачиваться горячей клавишей и кнопкой, а состояние MUST сохраняться между запусками.

#### Scenario: Сворачивание сайдбара
- **WHEN** пользователь нажимает Toggle Sidebar
- **THEN** сайдбар сжимается до иконок, содержимое расширяется, состояние сохраняется

#### Scenario: Перезапуск
- **WHEN** приложение перезапускается
- **THEN** сайдбар восстанавливает прежнее состояние (свёрнут или развёрнут)

### Requirement: Строчный компонент настроек
Настройки MUST читаться как строки «подпись и описание слева, контрол справа». Типы контролов:
переключатель, сегмент, ползунок, кнопка, поля ввода. Компоненты MUST жить в `src/components/ui/`.

#### Scenario: Отключённая настройка
- **WHEN** настройка недоступна в текущем состоянии
- **THEN** строка показывает причину и не реагирует на нажатие

### Requirement: Хранилище на SQLite
Данные MUST лежать в `data/tempo.db` рядом с исполняемым файлом в портативном режиме и в каталоге
приложения при установке. Каждая сущность MUST нести `id` (UUID), `updated_at` и `deleted_at`;
удаление MUST быть мягким. Компоненты MUST NOT выполнять SQL напрямую — только через `src/services/db.ts`.

#### Scenario: Первый запуск после обновления
- **WHEN** база отсутствует, а рядом лежит старый `alarmer.json`
- **THEN** будильники, задачи, заметки и настройки переносятся; программы и направления отбрасываются

#### Scenario: Портативный запуск
- **WHEN** приложение запущено из папки на любом диске
- **THEN** база и медиа создаются в `data/` рядом с `tempo.exe`, системный реестр не затрагивается

### Requirement: Переименование продукта
Продукт MUST называться Tempo: заголовок окна, `tempo.exe`, идентификатор `app.tempo.desktop`,
архив `tempo-v<tag>-portable-windows.zip`. Автообновление MUST работать после переименования;
URL манифеста MUST быть обновлён во всех трёх местах синхронно.

#### Scenario: Обновление portable-копии
- **WHEN** выходит новая версия
- **THEN** приложение сообщает об обновлении, скачивает архив с прогрессом, заменяет себя и перезапускается

### Requirement: Удаление программ-расписаний
Понятия программы и шага MUST быть удалены из интерфейса, типов и кода. Простые будильники MUST
остаться и MUST продолжать срабатывать в фоне.

#### Scenario: Старые программы в данных
- **WHEN** в перенесённых данных есть программы со шагами
- **THEN** они не появляются в интерфейсе и не звонят; будильники из шагов не создаются

#### Scenario: Будильник продолжает работать
- **WHEN** будильник установлен на время, приложение свёрнуто в трей
- **THEN** будильник звенит в назначенную минуту
